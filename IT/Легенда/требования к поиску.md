7. ИСТОЧНИКИ ПОИСКА
===========================================
- Рекомендации hh.ru по резюме (URL с resume=...). Этот источник
  сам не показывает вакансии, на которые уже откликался — можно
  спокойно перезапускать по мере роста списка.
  РАБОЧИЙ URL (найдено 21.09, старый /applicant/recommended_vacancies
  давал 404): https://hh.ru/search/vacancy?resume={ID_РЕЗЮМЕ}&schedule=remote&order_by=publication_time
  ID резюме "Python Backend-разработчик":
  c1cd7004ff10b8300e0039ed1f467256397433 (брать со страницы резюме,
  если поменяется). Без фильтра schedule=remote источник отдаёт
  600+ вакансий (слабое соответствие резюме, много нерелевантного —
  ML/Data Science/Go/Java и т.п.), поэтому фильтр remote обязателен.
  Даже с фильтром список всё равно ШИРЕ, чем заголовочный поиск
  (попадаются вакансии без слова python/backend в заголовке) — все
  равно применяется фильтр по заголовку (п.1) к каждой карточке.
  Пролистывать через &page=2, &page=3 и т.д. На 21.09 первые 5
  страниц (page=0..4) дали не так много новых кандидатов сверх
  заголовочного поиска "Python"/"Backend" — почти всё дублируется.
  Постранично идти дальше не обязательно каждый раз, если после
  первых 3-5 страниц новых подходящих карточек не находится.
- Поиск по заголовку (search_field=name), запрос просто "Python"
  без уточнений — он покрывает почти все более узкие фразы вида
  "Python разработчик", "python developer" и т.п., поэтому отдельно
  их гонять не нужно.
- ВАЖНО (найдено 02.08, до этого было пропущено несколько дней):
  запрос "Python" НЕ покрывает вакансии, где в заголовке вообще нет
  слова Python, а есть только "Backend"/"Бэкенд" — а такие вакансии
  тоже разрешены (см. пункт 1). Поэтому ОБЯЗАТЕЛЬНО отдельным
  запросом проверяю ещё и просто "Backend" (в заголовке, remote) —
  "Бэкенд" даёт тот же результат что и "Backend", хватает одного
  из двух. Без этого второго запроса часть подходящих вакансий
  (например "Senior Backend Engineer", "Тимлид backend
  разработчиков" без упоминания Python в названии) просто не
  находится.
