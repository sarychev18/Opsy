Задача AI-агент для поддержки сотрудников
Контекст
Компания разрабатывает AI-агента, который помогает сотрудникам поддержки работать с клиентскими запросами.
Сейчас сотрудник самостоятельно ищет информацию в различных системах: профиль клиента, платежи, операции, продукты, документы, обращения, риски.
Необходимо создать AI-агента, который принимает запрос сотрудника в свободной форме, ведёт диалог, получает информацию из внутренних систем, анализирует ситуацию и помогает выполнить необходимые действия.
Компания имеет большое количество внутренних сервисов с разными способами интеграции:
REST API; gRPC; GraphQL; Kafka события; базы данных.
Сценарии работы
1. Анализ проблемы клиента
Пример диалога:

Сотрудник: Почему клиент не может выполнить платеж?
AI: Укажите клиента и платеж
Сотрудник: Клиент 123, платеж 456
AI: Проверяю информацию...
Платеж отклонён. Причина: превышен лимит.
Агент должен: понять намерение пользователя; запросить недостающие данные; получить информацию из систем; сформировать ответ.
2. Подготовка профиля клиента
Запрос:
Подготовь клиента к звонку
Необходимо собрать данные из нескольких источников: профиль клиента; финансовая активность; история платежей; продукты; документы; обращения; риски; рекомендации.

Результат:
Профиль клиента: Общая информация Финансовая активность Проблемы Риски Рекомендации сотруднику
3. Выполнение действий
Пример:
Увеличь клиенту лимит платежей
Агент должен: проверить возможность операции; выполнить необходимые проверки; получить подтверждение человека; выполнить действие.
4. Работа с событиями
В системе есть события:
CUSTOMER_STATUS_CHANGED PAYMENT_BLOCKED DOCUMENT_READY

Например: клиент изменил статус → событие пришло через Kafka → агент должен учитывать актуальные данные при следующем запросе.
5. Длительные операции
Пример:
Подготовь большой отчёт по клиенту
Операция может занимать несколько минут. Необходимо учитывать:
выполнение после завершения HTTP-запроса; сохранение состояния; уведомление пользователя после завершения.
6. Неизвестная внешняя система
Появляется новая задача:
Добавить в агента данные из новой внешней системы.
Известно только: система принадлежит другой команде; документации нет; контракт неизвестен; способ интеграции неизвестен; SLA неизвестен.
Необходимо объяснить: какие вопросы задать владельцам системы; какие данные получить до начала разработки; как спроектировать интеграцию; как тестировать без доступа к реальной системе.

Доступные системы
Customer Service
Информация о клиенте. REST API.
Payment Service
Платежи и статусы операций. gRPC.
Product Service
Подключенные продукты клиента. GraphQL.
Risk Service
Риски и ограничения. gRPC.
Document Service
Документы. REST API + Kafka события.
Event Platform
События изменения данных. Kafka.

Дополнительные условия
При проектировании учитывать:
хранение состояния диалога; добавление новых сценариев; ошибки внешних систем; повторные запросы; частичное получение данных; восстановление после сбоев; контроль действий агента; масштабирование.
Ограничения
За время собеседования невозможно реализовать всю систему.
Необходимо:
1. Спроектировать архитектуру решения. 2. Выбрать часть функциональности для реализации. 3. Реализовать один рабочий сценарий. 4. Объяснить принятые решения и компромиссы.
Контракты внешних систем отсутствуют. Необходимо самостоятельно предложить необходимые интерфейсы и модели данных.
